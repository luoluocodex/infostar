## 1. 项目背景与内容分析

### 1.1 考纲权威范围（从 PDF 提取，为唯一内容边界）

**考核思想**：熟练掌握小学数学基础知识与 C++ 考纲语句；试题灵活性强、强调独立思考与逻辑思维；用计算机编程解决数学问题。

**数学范围**

- 小学 1–6 年级数学基础知识
- 参考小学培优教材、数学思想方法指导教材
- **对标国内名校小升初自主招生命题难度与题型**
- 信息学数学部分参照《信息学思维训练题》
- 指定参考书：《小学数学基础知识大全》《小学数学思想方法导引》

**信息学范围**

| 分类 | 考纲条目 |
|---|---|
| 编程环境 | Windows + Dev C++；编辑/编译/调试/运行/存取程序 |
| 语句 | ① 主程序框架 ② 数学表达式（`+ - * / % ()`，**特别注意整数运算与实数运算的差异**）③ 数据类型 `int / long / float` ④ 变量与常量、命名规则、`++` `--` ⑤ `cout` ⑥ `cin` ⑦ 条件式（`> >= < <= == !=`、`! && \|\|`）⑧ `if-else` ⑨ `for` ⑩ 一维/二维数组 ⑪ 复合语句（`if` + `for` 联用） |
| 算法与数据结构 | 查找（顺序查找、二分查找）；排序（选择排序、插入排序、冒泡排序）；枚举；递推；队列（入队、出队、遍历）；栈（入栈、出栈、遍历） |

**考核结构**

- **初试**：笔试 = 小学数学思考题 **70%** + 程序阅读与程序填空 **30%**
- **复试**：笔试 + 机试

> **关键推论**：初试是纯笔试、且数学占 7 成，复试才有机试。因此本 App 的**内容主线是数学思维**（区域 A/B/C 合计 240 题），**辅线是程序阅读与填空**（区域 D/E 合计 140 题），机试类「拼出完整程序」作为复试进阶内容放在后期阶段。这与「游戏化 + 手机端」的形态天然契合——手机不适合敲代码，但极适合**读程序、填程序、选答案、玩算法演示**。

### 1.3 从真题反推出的能力地图

对 2024 选拔卷与思维训练题做归纳，实际考察的能力分布如下（直接决定关卡设计）：

| 能力域 | 代表真题 | 背后算法思想 | 生活化类比（产品化抓手） |
|---|---|---|---|
| 数论与整除 | 除以 5 余 2、除以 6 余 3，最小是几 | 枚举 / 同余 | 分糖果分不匀，剩几个 |
| 周期与循环节 | 2 的 2024 次方的个位数 | 周期规律 | 星期几转圈圈、红绿灯 |
| 进制与规律数列 | 0,1,2,10,11,12,20…222222 是第几个 | 进制计数 | 只会数 0/1/2 的外星人 |
| 计数原理 | 上 8 级楼梯有几种走法 | **递推 / 斐波那契** | 爬楼梯、兔子生小兔 |
| 容斥原理 | 20 个数中三人都记住的至少几个 | 容斥 | 班里既会画画又会唱歌的同学 |
| 数位统计 | 1…9999 共写了几个 6 | 分类枚举 | 书本页码里藏了几个数字 |
| 最值分配 | a+b+c+d=36 时乘积最大 | 不等式 / 枚举优化 | 四个人分糖，怎么分才能乘积最大 |
| 二分答案雏形 | 15 本书连续分给 4 人，最快抄完 | **二分 + 贪心** | 分作业本，让最慢的人尽量快 |
| 递推路径计数 | 4×8 棋盘跳马有几种路线 | 动态规划雏形 | 棋子跳格子 |
| 图论计数 | 子图有多少种 | 图论 | 朋友之间连线 |
| 债务清算 | 4 人最少转账总金额 | 图论 / 网络流雏形 | 同学之间互相借钱 |
| 几何与度量 | 铁丝围长方形、等腰三角形顶角 | 图形与比例 | 用绳子围花园 |
| 行程与工程 | 相对开出求距离、每分钟 60 米迟到 | 行程模型 | 上学路上走得快慢 |
| 分数与比例 | 分子加 9 分母加几 | 分数基本性质 | 切蛋糕 |
| 程序阅读 | if-chain 最大值、for 嵌套求和 | 执行轨迹推演 | **可视化执行器直接命中** |
| 程序改错 | 最大公约数程序错在哪 | 语法 + 逻辑 | 找 Bug 侦探游戏 |

> **重要发现**：2024 真题「上 8 级楼梯有几种走法」「再过 10000 秒是几点」等，用「可视化执行 + 变量盒子」演示一遍，理解效率远高于讲公式。这正是本 App 的核心价值主张。

### 1.4 术语勘误说明（C5，本方案统一口径）

考纲原文存在两处明显笔误，**本方案及后续题库一律采用右侧的正确口径**：

| 考纲原文 | 问题 | 本方案统一口径 |
|---|---|---|
| 「6、**输出**语句 cin」 | `cin` 是**输入**语句（从键盘读入） | **`cin` = 输入语句**（收到一张纸条） |
| 「排序算法：**选大**排序」 | 考纲算法体系（配合插入/冒泡）应为「**选择**排序」 | **选择排序**（每次挑出最值放到一端） |
| 改错题示例中的 `#inlude` / `iostram` / `maln()` / `For` / `If` | 均为 `C++训练题.doc` 改错题的**刻意错误** | 作为「找 Bug」题型素材保留，不作勘误 |
| 考纲 ⑤ 与 ⑥ 都写「输出语句」 | 重复笔误 | ⑤ = `cout`（输出），⑥ = `cin`（输入） |

## 2. 总体目标

### 2.1 一句话定位

> **一个跑在手机浏览器里的「算法可视化剧场」**——把考纲里的每一种数学思想与 C++ 语句，演成一幕有生活场景的小剧；孩子在手机上**动手拖、动手选、看它跑**，在闯关中把枯燥的符号变成看得见的过程。

### 2.2 分项目标

**产品目标**

1. 覆盖考纲全部知识点，形成 6 大内容区、约 400 题的闯关地图。
2. 手机浏览器（iOS Safari / Android Chrome）单手持握即可完成全部学习与练习，**单手可玩、竖屏优先、无横向滚动**。
3. 建立「学 → 玩 → 练 → 得星 → 解锁」的完整闭环，单关时长 **2–5 分钟**，适配小学生注意力曲线。
4. 部署在自有 NAS 的 Docker 中，**一次部署、长期可用、无外部依赖**。

**学习目标**（可观测）

1. 学生能独立读懂考纲范围内的 C++ 程序并正确写出运行结果（对应初试 30%）。
2. 学生能把「爬楼梯 / 分糖果 / 排队伍」等生活场景，**主动对应**到递推 / 取余 / 排序等抽象概念。
3. 学生能在拖拽拼装中理解程序的**执行顺序**与**变量状态变化**。
4. 学生错题可回溯、可重练，形成个人薄弱点画像。

**技术目标**

1. 纯前端运行，无需联网即可继续使用已缓存内容（HTTPS 部署后由 Service Worker 提供，见 §9.3）。
2. 自研 C++ 子集可视化执行引擎，支持考纲列出的全部语句与一维/二维数组。
3. 自研轻量拖拽积木引擎，体积远小于 Blockly（目标 gzip 后 < 25 KB）。
4. 首屏（局域网内）加载 < 2 秒，交互响应 < 100 ms。

### 2.3 明确「不做」清单（C4，去重后 7 条）

- ❌ 不做真实 C++ 编译与自动判题（无后端沙箱）
- ❌ 不做用户注册、登录、云端同步、账号体系（进度只存本地，可导出文件迁移）
- ❌ 不做排行榜、社交、多人对战
- ❌ 不做宠物养成类重资产玩法
- ❌ 不依赖任何外部 CDN 或第三方服务（完全自包含，可离线）
- ❌ 不做服务端存储任何用户数据（学习记录不出手机）
- ❌ MVP 阶段不做自由代码编辑器（Phase 3 之后按需引入）

## 3. 用户画像与使用场景

**主用户：小学五/六年级学生（10–12 岁）**

- 设备：家长手机或平板，触摸操作，竖屏握持
- 注意力：单次连续专注约 10–15 分钟
- 认字量：可读完整句子，但**抽象术语需替换成生活语言**
- 动机：喜欢即时反馈、星星、解锁、小动画；对「错」有挫败感，需要温和提示

**次用户：家长 / 指导老师（观察者，非操作者）**

- 需求：知道孩子学到哪了、哪块弱、最近有没有坚持
- 交互：查看本地生成的「学习报告」，不参与答题

**典型使用场景**

| 场景 | 时长 | 产品响应 |
|---|---|---|
| 放学后在家练习 | 15–30 min | 常规闯关，自动续接上次进度 |
| 考前突击复习 | 30–60 min | 「错题重练」「真题擂台」模式 |
| 睡前碎片时间 | 5–10 min | 「每日一练」3 题，短平快 |
| 家长陪练 | 10–20 min | 关卡内「讲一讲」按钮，展示生活化解释 |
| 在外用移动网络 | 10–20 min | 经公网域名直接访问 NAS，内容与家里完全一致 |
| 无网络（坐车/旅行） | 任意 | 已缓存的关卡可离线继续，进度先存本地，联网后自然衔接 |

## 4. 产品设计：游戏化体系

### 4.1 闯关地图（线性）

```
┌──────────── 主页 = 世界地图 ────────────┐
│  [头像/昵称]  ⭐ 128/360   🔥 连击 3 天  │
│                                          │
│   ┌─ 区域 A：数数里的秘密 ─────────┐     │
│   │  ①②③④⑤⑥  (★★☆ 14/18)   │     │
│   └──────────────────────────────┘     │
│              ↓ 解锁                     │
│   ┌─ 区域 B：图形与生活 ───────────┐    │
│   │  ⑦⑧⑨🔒🔒🔒                │    │
│   └──────────────────────────────┘     │
│              ↓                          │
│   ┌─ 区域 C/D/E：思维训练营 · 语句村 · 算法剧场 ┐
│   │  🔒🔒🔒🔒🔒🔒                │    │
│   └──────────────────────────────┘     │
└──────────────────────────────────────────┘
```

**视觉规则**

- 课程按**区域（章节）→ 关卡（节点）**两级组织，节点用圆点，已完成填色、当前节点呼吸动效、未解锁灰暗带锁
- 区域之间用一条手绘感的路径连线，产生「旅程」感
- 地图可纵向滚动，**单列布局**，适配手机竖屏
- 每关卡片显示：关名、题型图标、已得星数（最多 3 星）

### 4.2 星级与解锁规则

| 星级 | 获得条件 |
|---|---|
| ★ | 完成本关全部小题 |
| ★★ | 首次作答正确率 ≥ 70% |
| ★★★ | 首次作答正确率 100%（或使用提示 ≤ 1 次且全对） |

- **解锁**：每区域需累计达到一定星数才解锁下一区域（例如区域 N 需前序累计 ≥ 60% 星数），避免「跳级劝退」
- **重玩降级**：重玩可刷新记录，但星星只取历史最高值，防止刷分焦虑
- **连击（Streak）**：连续天数练习，纯正向激励，中断不清零（改为「本次重新出发」），避免小学生挫败

### 4.3 单关游玩闭环（统一节奏）

```
【情境】生活化场景动画/插图 + 一句话问题
   ↓
【示范】「讲一讲」——用生活化语言解释背后的思想（可跳过）
   ↓
【动手】拖拽积木 / 选择 / 可视化运行
   ↓
【反馈】即时对错 + 温和解释 + 「为什么错」的变量高亮
   ↓
【结算】星级弹出 + 星星飞入地图 + 一句话知识卡片
```

### 4.4 「讲一讲」：生活化理解方法论（本项目的教学核心）

这是满足「**通过小学能理解的生活化知识理解深奥的数学知识**」的关键机制。每一关强制绑定一个生活化类比，并按固定四步展开：

1. **场景**：先讲孩子熟悉的事（"妈妈给你 20 颗糖，平均分给 3 个小朋友"）
2. **动手**：让孩子在屏幕上真的分一次（拖糖果）
3. **抽象**：把动作映射成符号（`20 / 3 = 6`，`20 % 3 = 2`）
4. **迁移**：回到 C++ 语句本身（`cout << 20 % 3;` → 2）

**生活化类比对照表（题库创作强制遵循）**

| 抽象概念 | 生活化类比 | 交互形式 |
|---|---|---|
| 变量 | 贴了标签的盒子，可以换里面的东西 | 拖动数字进盒子，盒子抖动更新 |
| 数据类型 int/long | 小盒子装小东西，大盒子装大东西；满了会溢出 | 盒子塞满爆开的动画 |
| 整数除法 `/` | 分糖果，只算能整份分出去的 | 糖果按堆拖分 |
| 取余 `%` | 分完剩下没分掉的几个 | 剩余糖果落在旁边 |
| 实数运算差异 | 切蛋糕，能切出半块 | 蛋糕切分动画 |
| `++` `--` | 电梯上升一层 / 下降一层 | 楼层指示器 |

### 6.2 核心模块一：C++ 子集可视化执行引擎（本项目技术核心）

**目标**：不编译，直接「解释执行」考纲范围内的 C++ 子集，并把每一步的状态变成可播放的动画帧。

**支持的语法子集（严格对齐考纲）**

```
程序结构     #include <iostream> / using namespace std; / int main(){ ... return 0; }
声明         int / long / float / double  a, b, c;   int a[100];   int a[10][10];
赋值         a = 表达式;      a++ / a-- / ++a / --a
表达式       + - * / %  与  ( ) 嵌套；关系 > >= < <= == !=；逻辑 ! && ||
输入输出     cin >> a >> b;      cout << a << " " << b << endl;
条件         if (条件) 语句  /  if (条件) {...} else {...}
循环         for (初始化; 条件; 步进) {...}
数组         一维 a[i]、二维 a[i][j]
```

**执行模型：三阶段流水线**

```
C++ 源码
   │  ① 词法分析 Lexer
   ▼
Token 流
   │  ② 语法分析 Parser（手写递归下降）
   ▼
AST（抽象语法树）
   │  ③ 解释执行 Interpreter（生成执行帧序列）
   ▼
Trace = [ Frame, Frame, Frame, ... ]
   │  ④ 可视化回放器（React 组件按帧渲染）
   ▼
变量盒子 / 数组网格 / 输出打字机 / 循环轮盘
```

**执行帧（Frame）数据结构**

```ts
interface Frame {
  step: number;                  // 第几步
  line: number;                  // 当前执行到源码第几行（用于高亮）
  col?: number;
  action: 'declare' | 'assign' | 'input' | 'output'
        | 'cond' | 'loop-init' | 'loop-test' | 'loop-step'
        | 'array-write' | 'array-read' | 'call' | 'return';
  vars: Record<string, VarSnapshot>;   // 这一步之后的全部变量快照
  stdout: string;                      // 到这一步为止的累计输出
  loopStack: LoopInfo[];               // 循环嵌套栈（用于轮盘渲染）
  note: string;                        // 中文人话解释，如「a 变成 8 了」
  highlight?: { varName?: string; arrayIndex?: number[] };  // 高亮对象
}

interface VarSnapshot {
  name: string;
  type: 'int' | 'long' | 'float' | 'double' | 'array' | 'array2d';
  value: number | string | number[] | number[][];
  changed: boolean;              // 本步是否变化（驱动闪烁动画）
  boxSize: 'small' | 'big';      // int 用小红盒，long 用大蓝盒（视觉区分）
}
```

**两条强制约定**

- **约定 G1（`cin` 语义，C6）**：`cin` 的取值**只从题目的预置用例读取**（`payload.testInput`），播放器按顺序「递纸条」，**绝不弹出交互式输入框**，避免孩子卡住或输入非法值。用例数量不足时构建期报错（见 §12.1 内容测试）。
- **约定 G2（积木/题库与引擎解耦，C7）**：题目所需代码**只允许使用本引擎已实现的语法子集**；题库构建期对每道 `code-*` 题做「语法子集白名单校验」，越界即构建失败。

**安全与健壮性**

- 步数上限 `MAX_STEPS = 20000`，超限中止并提示「这个循环好像跑不完哦」
- 解析失败给出**儿童化报错**：「第 3 行好像少了一个分号 `;`」
- 禁止任何 `eval` / `Function` 构造；纯 AST 求值，无代码注入风险
- 整数/实数除法语义严格区分：`int/int` 截断取整，含 `float`/`double` 则按浮点（考纲重点，Phase 2 强化）

**可视化组件映射**

| 执行动作 | 可视化表现 |
|---|---|
| `declare` | 一个新的盒子飞入「变量区」，显示名字和初值 |
| `assign` | 盒子里的数字变化 + 盒子抖动 + 数字滚动动画 |
| `output` | 底部「话筒区」打字机逐字冒出 |
| `cond` | 条件表达式高亮 + 真/假分岔路动画 |
| `loop-test` / `loop-step` | 循环轮盘指针转动，显示「第 3 圈」 |
| `array-write` | 对应格子点亮 + 数字落格 |
| `array-read` | 对应格子放大 + 数据飞出 |

**引擎单测基准**：对 `docs/reference/` 中每道程序阅读题，均需有「源码 + 输入 → 期望 Trace 末尾 stdout」的用例，覆盖率 100%。2024 卷 4 题的基准如下：

| 题号 | 输入 | 期望输出 |
|---|---|---|
| 1 | `7 3 8` | `8` |
| 2 | `3 12 4 3 5 6 7 2 8 7` | `2` |
| 3 | `7 3 8 6 4 2 1 3` | `8 6` |
| 4 | （无输入） | `385` |

### 6.3 核心模块二：拖拽积木引擎

**设计取舍**：不引入 Blockly（体积大、生成的积木块偏「图形化编程」，与考纲「写 C++ 语句」的目标偏离）。改为自研**「代码骨架 + 可拖槽位」**模式——保留真实 C++ 语法外观，只把易错片段变成积木。

**四种积木输入模式（难度递进）**

| 模式 | 说明 | 示例 | 引入阶段 |
|---|---|---|---|
| L1 填空式 | 代码骨架留 `___` 槽，拖入值/运算符/下标 | `if (a ___ b)` 槽里拖入 `>`；`a[i]=a[___]+a[___]` 槽里拖入 `i-1`/`i-2` | **Phase 1（MVP）** |
| L2 整行排序 | 打乱的整行语句按顺序拖排 | 把 `int main(){` … `}` 排对 | Phase 2 |
| L3 片体积木 | 拖入 `for (i=0; i<n; i++)` 这样的片段 | 拼出完整循环 | Phase 2 |
| L4 积木建程序 | 用积木区拖出完整程序达成题目目标 | 拼一个求最大值程序 | Phase 4 |

> **约定 G2 落地（C7）**：MVP **只实现 L1**，槽位类型限「数字 / 运算符 / 下标表达式（如 `i-1`）/ 变量名」。因此 MVP 的 `C01-05`「填上缺的那一句」**降级为填下标与运算符**（拖入 `i-1`、`i-2` 与 `+`），不要求拖出整段 `a[i-1]+a[i-2]`。完整的表达式/片体积木推迟到 Phase 2（任务 2.5 / 2.6）。

**交互细节（手机优先）**

- 积木**吸附**：拖到槽位附近 40px 内自动吸附并高亮
- **触觉反馈**：`navigator.vibrate(10)`（Android 支持，iOS 降级为缩放动画）
- **防误触**：长按 150ms 才进入拖拽，避免误划
- 积木区固定在屏幕底部，采用**横向可滚动托盘**，单手拇指可达
- 支持「点选 → 点击槽位」的备选方式（拖拽失败时的无障碍路径）
- **静态校验**：填入后立即做类型/语法合法性检查，给出即时反馈（不等到提交）

### 6.4 核心模块三：题库与内容引擎

- 题库以 **TypeScript 模块**形式分区域拆包（`import()` 动态加载），实现按需加载，避免首屏过大
- 每区域一个 chunk，进入区域时才加载，配合 PWA 预缓存策略
- 构建期用 Zod 对全部题库做 schema 校验 + 唯一 ID 校验 + 答案完整性校验 + **语法子集白名单校验**，**校验不过直接构建失败**

### 6.5 核心模块四：进度与存档

- 存储介质：**Dexie (IndexedDB)** 为主，localStorage 存轻量配置
- 存储内容：关卡星级、答题历史、错题本、连击天数、昵称头像、设置项
- **一键导出存档**：生成 `.json` 文件，通过 Web Share API / 下载链接保存到手机，用于换设备迁移或防误清
- **一键导入**：文件选择器读取恢复
- 云同步：不做

### 6.6 核心模块五：PWA 与离线

- `vite-plugin-pwa` 预缓存：HTML / JS / CSS / 图标 / 已加载题库 chunk
- 精确的 `manifest.webmanifest`：名称「信息学闯关」、竖屏 `portrait`、`display: standalone`、主题色
- 首次访问后自动提示「添加到主屏幕」引导层（iOS Safari 需手动教一次，配图示）
- 离线时：已缓存的关卡可正常闯关并本地存档；未缓存区域给出友好提示
- **渐进增强（重要）**：仅在 `https:` 协议下注册 Service Worker；若走的是 HTTP 入口则**静默跳过注册**，不报错、不弹警告，所有闯关功能不受影响（详见 §9.3）

┌───────────────────────────────────────────────────────────┐
│  手机浏览器（iOS Safari / Android Chrome）                 │

**架构简化说明**：由于选定纯前端、无登录，**后端被完全省略**——没有 Node 服务、没有数据库、没有判题沙箱。整个服务端就是一个 nginx 静态容器，资源占用 < 30 MB 内存，对 NAS 几乎零负担。公网访问由群晖反向代理 + Let's Encrypt 证书承担，容器本身只绑定回环端口。

### 7.3 题库 Schema（示意）

```ts
export const LevelSchema = z.object({
  id: z.string().regex(/^[A-F]\d{2}-\d{2}$/),   // 区域-章节-序号
  region: z.enum(['A','B','C','D','E','F']),
  chapter: z.string(),
  title: z.string(),
  type: z.enum([
    'math-choice','math-fill','math-step','math-manip',
    'code-read','code-fill','code-order','code-fix','code-build',
    'algo-demo','match'
  ]),
  // 生活化讲解（强制 4 段）
  life: z.object({
    scene:  z.string(),            // 1. 生活场景
    action: z.string(),            // 2. 动手做什么
    bridge: z.string(),            // 3. 抽象到符号
    backToCpp: z.string(),         // 4. 回到 C++ / 数学本身
  }),
  statement: z.string(),           // 题干
  payload: z.unknown(),            // 各题型专属数据（选项、代码、槽位、testInput）
  answer: z.unknown(),             // 标准答案
  explanation: z.string(),         // 答后解释
  hints: z.array(z.string()).max(3), // 最多 3 级提示
  stars: z.object({ two: z.number(), three: z.number() }),
  source: z.object({               // 来源标注
    kind: z.enum(['original','adapted','pastpaper']),
    from: z.string().optional(),   // 如「2024 选拔卷 第 11 题」
  }),
  difficulty: z.number().int().min(1).max(5),
});
```

> `code-*` 题型的 `payload` 额外要求：`code: string`（源码）、`testInput: number[]`（`cin` 预置用例，约定 G1）、`expectedStdout: string`（供构建期与引擎交叉验证）。

### Phase 1 · MVP（第一阶段，必须完成）

> **MVP 的定义**：不是「砍到只剩一半的成品」，而是**一条能完整走通的闭环**——从一个真实的孩子打开手机，到拿到星星、地图推进，中间不出现断路。内容量刻意做小，但**系统完整度必须是最终形态的缩影**。

1. 闯关地图页（2 区域、12 节点、星级显示、解锁逻辑）
2. 关卡页：情境 → 讲一讲 → 作答 → 即时反馈 → 结算，五段式闭环
3. **3 种题型**：`math-choice`、`math-fill`（数字键盘）、`code-read`（含可视化运行器）
4. **拖拽积木 v1**：仅 L1 填空式模式（拖数值/运算符/下标进槽位），支持吸附与点选备选路径
5. **可视化执行引擎 v1**：支持 `int` 变量、算术/关系/逻辑表达式、`cin`（预置用例）、`cout`、`if-else`、`for`、一维 `int a[]`；输出 Frame Trace
6. **执行播放器**：播放 / 暂停 / 单步 / 回退 / 变速（0.5x–2x）
7. **可视化组件**：变量盒子、输出打字机、循环轮盘、条件岔路、一维数组储物柜
8. 星级结算 + 星星飞入地图动画
9. 进度存档（Dexie）+ 一键导出/导入存档
10. PWA：可「添加到主屏幕」+ 已缓存内容离线可用
11. Docker 镜像构建 + 群晖部署脚本与说明（见 `guides/02`）

**MVP 明确不做**：`code-build`、`code-fix`（找 Bug）、`code-order`、二维数组、栈/队列可视化、错题本、学习报告、自由编辑器、多区域地图、L2+ 积木。

## 9. 部署方案（群晖 NAS / Docker / x86）

> 完整操作步骤见 [`guides/02-部署指南（群晖NAS）.md`](../guides/02-部署指南（群晖NAS）.md)。

### 9.1 容器化

**多阶段 Dockerfile（示意）**

```dockerfile
# ---------- 构建阶段 ----------
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run validate:content && npm run build

# ---------- 运行阶段 ----------
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
# 可选访问口令（见 §9.4-C）：把预生成的 .htpasswd 打进镜像
# COPY .htpasswd /etc/nginx/.htpasswd
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget -qO- http://127.0.0.1/ >/dev/null || exit 1
```

**docker-compose.yml（示意，含公网加固）**

```yaml
services:
  infostar:
    build: .
    image: infostar:latest
    container_name: infostar
    restart: unless-stopped
    # 关键加固：只绑定回环地址，端口不直接暴露给局域网与公网，
    # 所有外部访问统一经群晖反向代理（DSM nginx 在宿主机上，可访问 127.0.0.1）
    ports:
      - "127.0.0.1:8081:80"
    environment:
      - TZ=Asia/Shanghai
    read_only: true
    tmpfs:
      - /var/cache/nginx
      - /var/run
```

> 若希望**局域网内也能用 `http://NAS_IP:8081` 直连**（不经域名），把端口改成 `"8081:80"` 即可，但那样该端口会同时暴露到公网（若做了端口转发）。**推荐保持只有回环绑定**，用统一域名访问，规则更简单、攻击面更小。

**nginx.conf 关键点（容器内，含公网安全头）**

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    server_tokens off;          # 隐藏 nginx 版本号
    autoindex off;              # 禁止目录列表

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    # ---- 公网暴露所需的安全响应头 ----
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
    add_header Strict-Transport-Security "max-age=31536000" always;   # 由反向代理以 HTTPS 返回时生效
    # 纯静态、零外部请求，CSP 可以收紧到极严
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'self'" always;

    # 前端路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # hash 文件名强缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # Service Worker 与清单不缓存，保证更新生效
    location = /sw.js { add_header Cache-Control "no-cache"; }
    location = /manifest.webmanifest { add_header Cache-Control "no-cache"; }

    # 拒绝常见扫描与探测路径
    location ~ /\. { deny all; return 404; }
}
```

**群晖反向代理（DSM → 控制面板 → 登录门户 → 高级 → 反向代理）关键设置**

| 项 | 值 |
|---|---|
| 来源 | `HTTPS` / `你的域名` / `443` |
| 目的地 | `HTTP` / `127.0.0.1` / `8081` |
| 自定义标头 | 建议补 `X-Forwarded-Proto: https`（供日志与后续判断使用） |
| HSTS | 可在群晖「安全性 → 高级」中勾选，避免与容器头重复 |

> ⚠️ **反向代理只暴露这一个容器，绝不要给 DSM 管理端口（5000/5001）做端口转发。** 公网能碰到 DSM 登录页是 NAS 场景最常见的安全事故。

### 9.2 部署步骤（群晖 Container Manager）

**第一步：域名与网络打通**

1. 准备一个自有域名（如 `abc.com`），在域名商处添加一条 A 记录指向**家庭宽带的公网 IP**
2. 家庭宽带 IP 通常是动态的 → 用群晖 **控制面板 → 外部访问 → DDNS** 绑定
3. 路由器做端口转发：**只转发 80 与 443 到 NAS**，其余端口一律不开
4. 确认运营商**没有封禁 80/443**（家宽常见；若被封则改用 443 + 其他非标端口，或走 IPv6）

**第二步：部署容器**

5. 本机 `npm run build`，或用 Dockerfile 在 NAS 上构建
6. 群晖 **Container Manager → 项目 → 新增**，选择含 `docker-compose.yml` 的目录
7. 启动后用 `curl http://127.0.0.1:8081` 在 NAS 上本地验证容器正常

**第三步：反向代理与证书**

8. 群晖 **控制面板 → 登录门户 → 高级 → 反向代理**，按 §9.1 表格新增一条
9. 群晖 **控制面板 → 安全性 → 证书 → 新增 → 从 Let's Encrypt 获取证书**
   - 若 80 端口公网可达 → 走 **HTTP-01** 验证，一键完成
   - 若 80 被运营商封禁 → 改用 **DNS-01 验证**（需域名商的 API Key）
10. 在「安全性 → 证书 → 设置」中把证书绑定到该反向代理条目

**第四步：验证与安装**

11. 手机浏览器访问 `https://域名` → 检查地址栏有锁标志
12. 「添加到主屏幕」→ 从桌面图标启动，确认 `standalone` 模式正常
13. 用 Chrome DevTools → Application → Service Workers 确认 **SW 已注册**
14. 在路由器为 NAS 保留固定局域网 IP

**第五步：局域网访问优化（可选但推荐）**

15. 若路由器**不支持 NAT 回环（hairpin）**，家里访问 `https://域名` 会失败或绕公网。装 **群晖 DNS Server** 或使用路由器的「本地 DNS 覆盖」，把该域名在内网解析到 NAS 的**内网 IP**
16. 这样内外统一走 `https://域名`，局域网内直连 NAS 速度最快，且 SW 与存档体验完全一致

### 9.3 HTTPS 与 PWA 离线

**背景**：浏览器安全策略规定，**Service Worker 仅在 HTTPS 或 `localhost` 下才能注册**。若只用 `http://192.168.x.x:8081` 直连，PWA 离线缓存与完整「添加到主屏幕」体验会失效。

**结论**：采用**自有域名 + Let's Encrypt 免费证书**，HTTPS、PWA 离线、公网访问三者一次到位。

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. 自有域名 + Let's Encrypt（采用）** | 域名 A 记录 → 家庭公网 IP；群晖 DDNS 保持同步；路由器只转发 80/443；群晖反向代理挂证书 | ✅ **采用** |
| B. 群晖自签证书 | 无域名，纯自签 | 备选。零成本，但每台手机首次需手动信任证书 |
| C. 仅 HTTP 在线 | 不做 HTTPS | 降级预案。**其余功能全部正常**，仅损失「断网可用」 |

**产品侧兜底**：PWA 离线一律做成**渐进增强**——检测到 `serviceWorker in navigator` 且非 `http:` 时才注册；否则静默降级，不报错、不弹警告、不影响任何闯关功能。

### 9.4 公网暴露安全加固清单

本项目**攻击面极小**——纯静态、无后端、无数据库、无登录、无用户数据上传（进度都存在访客自己的手机里）。仍需完成以下加固：

**A. 网络层（最重要）**

- ✅ **只转发 80 / 443**，其余端口一律不转发
- ✅ **绝不为 DSM 管理端口（5000/5001）做端口转发**
- ✅ 容器端口绑定回环 `127.0.0.1:8081:80`，不直接对公网开放
- ✅ 关闭路由器上的 UPnP（防止其他设备自行开洞）
- ✅ 若路由器支持，仅开放 IPv4 或仅 IPv6，减少暴露面
- ✅ NAS 管理员账号启用**两步验证 + 强密码 + 自动封锁（Auto Block）**

**B. 应用层**

- ✅ nginx 安全响应头（`nosniff` / `X-Frame-Options` / `Referrer-Policy` / `HSTS` / 严格 `CSP`）
- ✅ `server_tokens off` 隐藏版本号，`autoindex off` 禁止目录列表
- ✅ 拒绝点文件（`location ~ /\. { deny all; }`）
- ✅ 放置 `robots.txt` 禁止收录：`User-agent: *` + `Disallow: /`
- ✅ 反向代理层加**限流**（`limit_req`，如 20 r/s 单 IP）
- ✅ 关闭不需要的 HTTP 方法（只允许 `GET` / `HEAD`）

**C. 访问口令（推荐加上）——层级说明（C8）**

因为应用本身无登录，公网可达意味着**任何拿到域名的人都能访问**。最轻量做法是加一层 **HTTP Basic Auth**。**加在哪一层？**

| 方案 | 做法 | 评价 |
|---|---|---|
| **C-1. 容器 nginx 层（推荐）** | 本地 `htpasswd -c .htpasswd 用户名` 生成，`Dockerfile` 里 `COPY .htpasswd /etc/nginx/.htpasswd`，nginx `location /` 加 `auth_basic` | ✅ 随镜像一起版本化，一次配置到处生效；群晖反向代理无需改动 |
| C-2. 群晖反向代理层 | 在群晖反向代理的「自定义标头」或 DSM 前置 nginx 里加 `auth_basic` | 可行但配置分散、不易版本管理 |
| C-3. 不做 | 公开可访问 | 若不在意被访问可选 |

```nginx
# 容器 nginx 层示例（对应 C-1）
location / {
    auth_basic "Restricted";
    auth_basic_user_file /etc/nginx/.htpasswd;
    try_files $uri $uri/ /index.html;
}
```

- 优点：5 分钟配置，零改代码，能挡住所有爬虫与路人
- 代价：家庭成员需输入一次口令（浏览器会记住；iOS 添加到主屏幕后同样会记住）

**D. 运维层**

- ✅ 定期更新 `nginx:alpine` 基础镜像，重跑安全扫描
- ✅ 群晖开启「通知」，异常登录尝试邮件提醒
- ✅ 每季度检查一次群晖「日志中心 → 连接日志」
- ✅ 不使用时可通过群晖反向代理一键停用该条目（容器继续跑，只是不对外）

## 15. 结论

本方案以**考纲为唯一内容边界**，以**纯前端可视化执行**为技术抓手，以**「生活化类比四步法」**为教学内核，以**闯关地图 + 星级**为动机系统，以**群晖 Docker 单容器 + 反向代理**为交付形态，形成一条「内容有据、技术可控、体验适配手机、部署维护极简」的完整路径。

v2.0 在 v1.0 的基础上完成了文档重组（`plan/ reference/ guides/`）与九项一致性修订（C1–C9），把内容配比、题量分配、术语口径、`cin` 与积木的工程约定全部对齐，使方案从「蓝图」升级为「可直接照着执行的施工图」。

**关键建议**：第一阶段（MVP）不要贪多，**只做 2 个主题 12 关，但必须把整条闭环跑通**——地图、关卡、答题、可视化运行、星级、存档、PWA、部署，一个都不能少。闭环打通后，剩下的工作就变成了「往一个已经跑通的容器里不断加内容」，风险与成本都会大幅下降。
