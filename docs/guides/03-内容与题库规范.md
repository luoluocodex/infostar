## 1. 一条数据 = 一道题

每道题是一份「**场景 + 讲解 + 题目 + 解释**」四段式记录，落库为标准 TS 模块（见 `content/schema.ts`）。

### 1.1 完整字段（Zod Schema）

```ts
import { z } from 'zod';

export const LevelSchema = z.object({
  id: z.string().regex(/^[A-F]\d{2}-\d{2}$/),      // 区域 + 章节 2 位 + 序号 2 位
  region: z.enum(['A','B','C','D','E','F']),
  chapter: z.string(),                              // 章节名，如「爬楼梯的秘密」
  title: z.string(),                                // 关名，如「小明上楼梯」
  type: z.enum([
    'math-choice','math-fill','math-step','math-manip',
    'code-read','code-fill','code-order','code-fix','code-build',
    'algo-demo','match',
  ]),

  // ★ 生活化讲解：四段式，缺一不可
  life: z.object({
    scene:     z.string(),   // 1 场景：孩子熟悉的事
    action:    z.string(),   // 2 动手：在屏幕上做什么
    bridge:    z.string(),   // 3 抽象：映射成符号 / 表达式
    backToCpp: z.string(),   // 4 迁移：回到 C++ 或数学本身
  }),

  statement: z.string(),                            // 题干（小学语言）
  payload: z.unknown(),                             // 题型专属数据（见 §2）
  answer: z.unknown(),                              // 标准答案
  explanation: z.string(),                          // 答后解释（温和、讲「为什么」）
  hints: z.array(z.string()).max(3),                // ≤3 级提示，不给答案
  stars: z.object({ two: z.number(), three: z.number() }),
  source: z.object({
    kind: z.enum(['original','adapted','pastpaper']),
    from: z.string().optional(),                    // 如「2024 选拔卷 第 11 题」
    note: z.string().optional(),                    // 改编说明
  }),
  difficulty: z.number().int().min(1).max(5),
});

export type Level = z.infer<typeof LevelSchema>;
```

## 2. 题型 × payload × answer

| 题型 | payload 结构 | answer 结构 |
|---|---|---|
| `math-choice` | `{ options: {key,text,svg?}[], multi?: boolean }` | `string`（正确 option.key） |
| `math-fill` | `{ unit?: string, allowFraction?: boolean }` | `string`（数字或分数，如 `"34"`、`"3/4"`） |
| `math-step` | `{ steps: {prompt,payload,answer}[] }` | 各步答案数组 |
| `math-manip` | `{ canvas: 'stairs'\|'grid'\|'slider'\|'candy'\|..., goal: string, init: unknown }` | `unknown`（按交互类型的达成态） |
| `code-read` | `{ code: string, testInput: number[], expectedStdout: string, showRunner?: boolean }` | `string`（期望输出） |
| `code-fill` | `{ skeleton: string, slots: {id,accept:('num'\|'op'\|'index'\|'var')[],answer:string}[] }` | `Record<slotId,string>` |
| `code-order` | `{ lines: string[] }`（打乱） | `number[]`（正确顺序的行索引） |
| `code-fix` | `{ code: string, errorLines: number[] }` | `number[]`（错误行） |
| `code-build` | `{ palette: string[], goal: string, testInput: number[], expectedStdout: string }` | `string`（正确程序，规范化后比对） |
| `algo-demo` | `{ demo: 'stack'\|'queue'\|'binary'\|'sort-select'\|..., ops: unknown[] , question: ... }` | 按 demo 类型 |
| `match` | `{ left: {id,text}[], right: {id,text}[] }` | `{leftId:rightId}[]` |

### 2.1 `code-*` 题的三条硬约束

1. **`code` 只能使用引擎已实现的语法白名单**：`int/long/float/double`、`+ - * / %`、关系/逻辑运算、`cin`/`cout`、`if-else`、`for`、一维/二维数组、`#include <iostream>`、`using namespace std;`、`int main()`、`return 0;`。**禁止 `while`、函数、指针、结构体、`switch`、字符串。** 构建期白名单校验，越界即失败。
2. **约定 G1**：`testInput` 必须覆盖程序所有 `cin` 读取次数，不多不少；运行时按顺序「递纸条」，**不弹输入框**。
3. **`expectedStdout` 必须与引擎实际输出逐字符一致**（交叉验证脚本比对）；否则构建失败。

示例（来自 2024 选拔卷 第 3 题，`adapted`）：

```ts
{
  id: 'D02-03',
  type: 'code-read',
  payload: {
    code: `#include <iostream>
using namespace std;
int main(){
  int n,j,k,i,a;
  cin>>n; j=0;k=0;
  for(i=1;i<=n;i++){
    cin>>a;
    if(a>j){ k=j;j=a; }
    else if(a>k) k=a;
  }
  cout<<j<<" "<<k;
}`,
    testInput: [7,3,8,6,4,2,1,3],
    expectedStdout: '8 6',
  },
  answer: '8 6',
  source: { kind: 'adapted', from: '2024 选拔卷 程序阅读 第 3 题', note: '题干改为生活化问法，保留程序原样' },
}
```

## 3. 生活化讲解（教学核心，强制四段式）

每道题必须绑定一个生活化类比，按 **场景 → 动手 → 抽象 → 迁移** 四步写：

| 步骤 | 要求 | 反例（不可接受） |
|---|---|---|
| 场景 scene | 讲孩子熟悉的事，有具体人和物 | 「本题考察取余运算」 |
| 动作 action | 在屏幕上真的做一次的动作描述 | 「理解取余概念」 |
| 抽象 bridge | 把动作映射成符号/公式 | 直接给公式 |
| 迁移 backToCpp | 落到 C++ 语句或数学结论 | 无 |

**好的示例（D01-04 剩下几颗糖）**

- scene：妈妈买了 20 颗糖，要平均分给 3 个小朋友。
- action：把糖一颗颗拖到 3 个小盘子里，能整份分掉多少颗？还剩几颗？
- bridge：`20 ÷ 3` 能分掉 6 颗一份共 18 颗；剩下 2 颗分不动了 → 写作 `20 % 3 = 2`。
- backToCpp：`cout << 20 % 3;` 屏幕上就会出现 `2`。

## 4. 来源标注（可追溯）

| kind | 含义 | 必填 | 要求 |
|---|---|---|---|
| `original` | 完全原创 | — | 需二次人工复核 |
| `adapted` | 真题改编 | `from` + `note` | 写清原题出处与改了什么 |
| `pastpaper` | 真题原题 | `from` | **默认不允许**；确需原样使用时须确认版权边界（见主方案 §1.2） |

> 策略：**优先 `adapted`**——保留真题的思维价值，但改数值、改情境、补图形，既规避版权又贴合生活化教学。

## 5. 难度与星级

| 难度 | 占比 | 定位 |
|---|---|---|
| 1 入门 | 20% | 每章前 1–2 关，建立信心 |
| 2 基础 | 30% | 概念巩固 |
| 3 标准 | 30% | 对标真题常规题 |
| 4 进阶 | 15% | 对标真题压轴 |
| 5 挑战 | 5% | 决赛/复试级 |

星级门槛：★ = 完成全部小题；★★ = 首次正确率 ≥ 70%；★★★ = 首次 100%（或提示 ≤ 1 次且全对）。`stars.two` / `stars.three` 存该关小题的对应正确数。

## 6. 单题创作检查清单（提交前逐项打勾）

- [ ] 四段式 `life` 齐全，且**场景具体、不讲术语**
- [ ] 只用考纲内知识点（不越界到 while / 函数 / 指针 / 结构体）
- [ ] `code-*` 代码在**语法白名单**内
- [ ] `code-*` 的 `testInput` 覆盖全部 `cin`；`expectedStdout` 与引擎输出一致
- [ ] 选择题答案唯一；填空题明确是否接受等价写法（如 `6` 与 `6.0`）
- [ ] 难度 1–5 且与相邻关平滑递增
- [ ] `hints` ≤ 3 条，提示**不给答案**
- [ ] `explanation` 用小学语言，无「复杂度 / 时间复杂度 / 算法」等词
- [ ] 角色名统一（小明 / 小红）
- [ ] 插画为自绘 SVG，单关体积达标（总增包 ≤ 120 KB / 12 关）
- [ ] `source` 标注正确；`adapted` 必带 `from` + `note`

---

## 7. 新增一关的标准流程

1. 确定区域与章节 → 定 `id`（如 `C02-04`）。
2. 选生活化类比 → 写四段式 `life`。
3. 写 `statement` 与 `payload`（按 §2 结构）。
4. 定 `answer`、`explanation`、`hints`、`stars`、`difficulty`、`source`。
5. `code-*` 题：先在引擎里跑一遍，把真实输出作为 `expectedStdout`。
6. 落库到 `src/content/regionX_*/<章节>.ts`。
7. 跑 `npm run validate:content` → 通过后提交（校验不过禁止合并）。

## 8. 常见错误（构建期会拦下）

| 错误 | 后果 |
|---|---|
| `id` 重复或不符合正则 | 构建失败 |
| `answer` 与 `payload.options` 对不上 | 构建失败 |
| `code` 用到白名单外语法 | 构建失败 |
| `testInput` 数量与 `cin` 次数不匹配 | 构建失败 |
| `expectedStdout` 与引擎输出不一致 | 交叉验证失败 |
| `life` 四段缺项 | Schema 校验失败 |
| `hints` 超过 3 条 | Schema 校验失败 |
