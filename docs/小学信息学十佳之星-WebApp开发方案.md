## 1. 项目背景与内容分析

### 1.1 考纲权威范围（从 PDF 提取，为唯一内容边界）

**考核思想**：熟练掌握小学数学基础知识与 C++ 考纲语句；试题灵活性强、强调独立思考与逻辑思维；用计算机编程解决数学问题。

**数学范围**

- 小学 1–6 年级数学基础知识
- 参考小学培优教材、数学思想方法指导教材
- **对标国内名校小升初自主招生命题难度与题型**
- 信息学数学部分参照《信息学思维训练题》
- 指定参考书：《小学数学基础知识大全》《小学数学思想方法导引》

**信息学范围**

| 分类 | 考纲条目 |
|---|---|
| 编程环境 | Windows + Dev C++；编辑/编译/调试/运行/存取程序 |
| 语句 | ① 主程序框架 ② 数学表达式（`+ - * / % ()`，**特别注意整数运算与实数运算的差异**）③ 数据类型 `int / long / float` ④ 变量与常量、命名规则、`++` `--` ⑤ `cout` ⑥ `cin` ⑦ 条件式（`> >= < <= == !=`、`! && \|\|`）⑧ `if-else` ⑨ `for` ⑩ 一维/二维数组 ⑪ 复合语句（`if` + `for` 联用） |
| 算法与数据结构 | 查找（顺序查找、二分查找）；排序（选择排序、插入排序、冒泡排序）；枚举；递推；队列（入队、出队、遍历）；栈（入栈、出栈、遍历） |

**考核结构（决定产品内容权重）**

- **初试**：笔试 = 小学数学思考题 **70%** + 程序阅读与程序填空 **30%**
- **复试**：笔试 + 机试

> **关键推论**：初试权重 7:3，且全部为笔试。因此本 App 的内容配比应以 **数学思维为主线（约 70%）**、**程序阅读/填空为副线（约 30%）**，机试类编程题作为复试进阶内容放在后期阶段。这与「游戏化 + 手机端」的形态天然契合——手机不适合敲代码，但极适合做**读程序、填程序、选答案、玩算法演示**。

### 1.3 从真题反推出的能力地图

对 2024 选拔卷与思维训练题做归纳，实际考察的能力分布如下（这直接决定关卡设计）：

| 能力域 | 代表真题 | 背后算法思想 | 生活化类比（产品化抓手） |
|---|---|---|---|
| 数论与整除 | 除以 5 余 2、除以 6 余 3，最小是几 | 枚举 / 同余 | 分糖果分不匀，剩几个 |
| 周期与循环节 | 2 的 2024 次方的个位数 | 周期规律 | 星期几转圈圈、红绿灯 |
| 进制与规律数列 | 0,1,2,10,11,12,20…222222 是第几个 | 进制计数 | 只会数 0/1/2 的外星人 |
| 计数原理 | 上 8 级楼梯有几种走法 | **递推 / 斐波那契** | 爬楼梯、兔子生小兔 |
| 容斥原理 | 20 个数中三人都记住的至少几个 | 容斥 | 班里既会画画又会唱歌的同学 |
| 数位统计 | 1…9999 共写了几个 6 | 分类枚举 | 书本页码里藏了几个数字 |
| 最值分配 | a+b+c+d=36 时乘积最大 | 不等式 / 枚举优化 | 四个人分糖，怎么分才能乘积最大 |
| 二分答案雏形 | 15 本书连续分给 4 人，最快抄完 | **二分 + 贪心** | 分作业本，让最慢的人尽量快 |
| 递推路径计数 | 4×8 棋盘跳马有几种路线 | 动态规划雏形 | 棋子跳格子 |
| 图论计数 | 子图有多少种 | 图论 | 朋友之间连线 |
| 债务清算 | 4 人最少转账总金额 | 图论 / 网络流雏形 | 同学之间互相借钱 |
| 几何与度量 | 铁丝围长方形、等腰三角形顶角 | 图形与比例 | 用绳子围花园 |
| 行程与工程 | 相对开出求距离、每分钟 60 米迟到 | 行程模型 | 上学路上走得快慢 |
| 分数与比例 | 分子加 9 分母加几 | 分数基本性质 | 切蛋糕 |
| 程序阅读 | if-chain 最大值、for 嵌套求和 | 执行轨迹推演 | **可视化执行器直接命中** |
| 程序改错 | 最大公约数程序错在哪 | 语法 + 逻辑 | 找 Bug 侦探游戏 |

> **重要发现**：2024 真题里的「第 9 题爬楼梯」和「第 13 题时间计算」等，用「可视化执行 + 变量盒子」演示一遍，孩子的理解效率远高于讲公式。这正是本 App 的核心价值主张。

## 2. 总体目标

### 2.1 一句话定位

> **一个跑在手机浏览器里的「算法可视化剧场」**——把考纲里的每一种数学思想与 C++ 语句，演成一幕有生活场景的小剧；孩子在手机上**动手拖、动手选、看它跑**，在闯关中把枯燥的符号变成看得见的过程。

### 2.2 分项目标

**产品目标**

1. 覆盖考纲全部知识点，形成 5 大内容区、约 350–400 题的闯关地图。
2. 手机浏览器（iOS Safari / Android Chrome）单手持握即可完成全部学习与练习，**单手可玩、竖屏优先、无横向滚动**。
3. 建立「学 → 玩 → 练 → 得星 → 解锁」的完整闭环，单关时长控制在 **2–5 分钟**，适配小学生注意力曲线。
4. 部署在自有 NAS 的 Docker 中，**一次部署、长期可用、无外部依赖**。

**学习目标**（可观测）

1. 学生能独立读懂考纲范围内的 C++ 程序并正确写出运行结果（对应初试 30%）。
2. 学生能把「爬楼梯 / 分糖果 / 排队伍」等生活场景，**主动对应**到递推 / 取余 / 排序等抽象概念。
3. 学生能在拖拽拼装中理解程序的**执行顺序**与**变量状态变化**。
4. 学生错题可回溯、可重练，形成个人薄弱点画像。

**技术目标**

1. 纯前端运行，无需联网即可继续使用已缓存内容（见 §9.3 的 HTTPS 前置条件）。
2. 自研 C++ 子集可视化执行引擎，支持考纲列出的全部语句与一维/二维数组。
3. 自研轻量拖拽积木引擎，体积远小于 Blockly（目标 gzip 后 < 25 KB）。
4. 首屏（局域网内）加载 < 2 秒，交互响应 < 100 ms。

### 2.3 明确「不做」清单（防止范围蔓延）

- ❌ 不做真实 C++ 编译与自动判题（无后端沙箱）
- ❌ 不做用户注册、登录、云端同步
- ❌ 不做排行榜、不做社交、不做多人对战
- ❌ 不做宠物养成类重资产玩法
- ❌ 不做公网访问与外部 CDN 依赖（完全自包含）
- ❌ MVP 阶段不做自由代码编辑器（Phase 3 之后按需引入）

## 3. 用户画像与使用场景

**主用户：小学五/六年级学生（10–12 岁）**

- 设备：家长手机或平板，触摸操作，竖屏握持
- 注意力：单次连续专注约 10–15 分钟
- 认字量：可读完整句子，但**抽象术语需替换成生活语言**
- 动机：喜欢即时反馈、星星、解锁、小动画；对「错」有挫败感，需要温和提示

**次用户：家长 / 指导老师（观察者，非操作者）**

- 需求：知道孩子学到哪了、哪块弱、最近有没有坚持
- 交互：查看本地生成的「学习报告」，不参与答题

**典型使用场景**

| 场景 | 时长 | 产品响应 |
|---|---|---|
| 放学后在家练习 | 15–30 min | 常规闯关，自动续接上次进度 |
| 考前突击复习 | 30–60 min | 「错题重练」「真题擂台」模式 |
| 睡前碎片时间 | 5–10 min | 「每日一练」3 题，短平快 |
| 家长陪练 | 10–20 min | 关卡内「讲一讲」按钮，展示生活化解释 |
| 无网络（外出） | 任意 | 已缓存的关卡可离线继续（需 HTTPS） |

## 4. 产品设计：游戏化体系

### 4.1 闯关地图（采用确认项 3-A）

```
┌──────────── 主页 = 世界地图 ────────────┐
│  [头像/昵称]  ⭐ 128/360   🔥 连击 3 天  │
│                                          │
│   ┌─ 区域 1：数数里的秘密 ─────────┐     │
│   │  ①②③④⑤⑥  (★★☆ 14/18)   │     │
│   └──────────────────────────────┘     │
│              ↓ 解锁                     │
│   ┌─ 区域 2：盒子里的数字 ─────────┐    │
│   │  ⑦⑧⑨🔒🔒🔒                │    │
│   └──────────────────────────────┘     │
│              ↓                          │
│   ┌─ 区域 3：当程序开始转圈 ───────┐    │
│   │  🔒🔒🔒🔒🔒🔒                │    │
│   └──────────────────────────────┘     │
└──────────────────────────────────────────┘
```

**视觉规则**

- 课程按**区域（章节）→ 关卡（节点）**两级组织，节点用圆点，已完成填色、当前节点呼吸动效、未解锁灰暗带锁
- 区域之间用一条手绘感的路径连线，产生「旅程」感
- 地图可纵向滚动，**单列布局**，适配手机竖屏
- 每关卡片显示：关名、题型图标、已得星数（最多 3 星）

### 4.2 星级与解锁规则

| 星级 | 获得条件 |
|---|---|
| ★ | 完成本关全部小题 |
| ★★ | 首次作答正确率 ≥ 70% |
| ★★★ | 首次作答正确率 100%（或使用提示 ≤ 1 次且全对） |

- **解锁**：每区域需累计达到一定星数才解锁下一区域（例如区域 N 需前序累计 ≥ 60% 星数），避免「跳级劝退」
- **重玩降级**：重玩可刷新记录，但星星只取历史最高值，防止刷分焦虑
- **连击（Streak）**：连续天数练习，纯正向激励，中断不清零（改为「本次重新出发」），避免小学生挫败

### 4.3 单关游玩闭环（统一节奏）

```
【情境】生活化场景动画/插图 + 一句话问题
   ↓
【示范】「讲一讲」——用生活化语言解释背后的思想（可跳过）
   ↓
【动手】拖拽积木 / 选择 / 可视化运行
   ↓
【反馈】即时对错 + 温和解释 + 「为什么错」的变量高亮
   ↓
【结算】星级弹出 + 星星飞入地图 + 一句话知识卡片
```

### 4.4 「讲一讲」：生活化理解方法论（本项目的教学核心）

这是满足「**通过小学能理解的生活化知识理解深奥的数学知识**」的关键机制。每一关强制绑定一个生活化类比，并按固定四步展开：

1. **场景**：先讲孩子熟悉的事（"妈妈给你 20 颗糖，平均分给 3 个小朋友"）
2. **动手**：让孩子在屏幕上真的分一次（拖糖果）
3. **抽象**：把动作映射成符号（`20 / 3 = 6`，`20 % 3 = 2`）
4. **迁移**：回到 C++ 语句本身（`cout << 20 % 3;` → 2）

**生活化类比对照表（题库创作强制遵循）**

| 抽象概念 | 生活化类比 | 交互形式 |
|---|---|---|
| 变量 | 贴了标签的盒子，可以换里面的东西 | 拖动数字进盒子，盒子抖动更新 |
| 数据类型 int/long | 小盒子装小东西，大盒子装大东西；满了会溢出 | 盒子塞满爆开的动画 |
| 整数除法 `/` | 分糖果，只算能整份分出去的 | 糖果按堆拖分 |
| 取余 `%` | 分完剩下没分掉的几个 | 剩余糖果落在旁边 |
| 实数运算差异 | 切蛋糕，能切出半块 | 蛋糕切分动画 |
| `++` `--` | 电梯上升一层 / 下降一层 | 楼层指示器 |
| `cout` | 对着话筒念出来 | 打字机效果输出 |
| `cin` | 别人递给你一张纸条 | 气泡输入 |
| `if-else` | 出门看天气：下雨带伞，否则戴帽子 | 岔路口二选一 |
| 条件式 `&& \|\| !` | 「既…又…」「或者」「不是」 | 开关组合电路 |
| `for` 循环 | 每天刷牙；跳格子一格一格跳 | 循环轮盘转一圈 |
| 一维数组 | 一排储物柜，每格一个编号 | 柜子格子可点亮 |
| 二维数组 | 电影院的座位表（几排几号） | 座位网格 |
| 顺序查找 | 一排书一本一本翻 | 手指逐格移动 |
| 二分查找 | 猜数字（1–100 猜几次）；字典查字 | 范围逐次折半高亮 |
| 选择排序 | 排队按身高，每次挑出最矮的站前面 | 队列重排动画 |
| 插入排序 | 整理手里的一把扑克牌 | 抽牌插入 |
| 冒泡排序 | 水里泡泡大的往上浮 | 相邻比较冒泡 |
| 枚举 | 试开三位密码锁，一个一个试 | 密码轮转动 |
| 递推 | 爬楼梯（一步 1 级或 2 级）；兔子生小兔 | 楼梯台阶累加计数 |
| 队列 | 排队买奶茶，先来的先买 | 队伍前进动画 |
| 栈 | 叠盘子，最后放的先拿走；浏览器后退 | 盘子叠放/取走 |
| 周期 | 星期几转圈圈；红绿灯循环 | 圆环指针 |
| 容斥 | 班里既会画画又会唱歌的人有几个 | 两个圈重叠 |
| 进制 | 只会数 0/1/2 的外星人怎么数数 | 三格计数器 |
| 数位统计 | 书本页码里出现了几个「6」 | 翻页高亮 |
| 二分答案 | 分作业本，想办法让抄得最慢的人尽量快 | 工作量柱状图调平 |
| 路径计数 | 棋子跳格子有多少条路 | 棋盘路径点亮 |
| 图论 / 最少转账 | 同学之间互相借钱，怎么还得最少 | 箭头图 + 转账次数减少 |
| 最值分配 | 四个人分糖，怎么分乘积最大 | 滑块调整分配 |
| 行程问题 | 上学走路，走快一点就早到 | 双人赛道动画 |

## 5. 内容体系（最终形态）

### 5.1 五大内容区

| 区域 | 名称 | 覆盖考纲 | 目标题量 | 核心玩法 |

### 6.2 核心模块一：C++ 子集可视化执行引擎（本项目技术核心）

**目标**：不编译，直接「解释执行」考纲范围内的 C++ 子集，并把每一步的状态变成可播放的动画帧。

**支持的语法子集（严格对齐考纲）**

```
程序结构     #include <iostream> / using namespace std; / int main(){ ... return 0; }
声明         int / long / float / double  a, b, c;   int a[100];   int a[10][10];
赋值         a = 表达式;      a++ / a-- / ++a / --a
表达式       + - * / %  与  ( ) 嵌套；关系 > >= < <= == !=；逻辑 ! && ||
输入输出     cin >> a >> b;      cout << a << " " << b << endl;
条件         if (条件) 语句  /  if (条件) {...} else {...}
循环         for (初始化; 条件; 步进) {...}
数组         一维 a[i]、二维 a[i][j]
```

**执行模型：三阶段流水线**

```
C++ 源码
   │  ① 词法分析 Lexer
   ▼
Token 流
   │  ② 语法分析 Parser（手写递归下降）
   ▼
AST（抽象语法树）
   │  ③ 解释执行 Interpreter（生成执行帧序列）
   ▼
Trace = [ Frame, Frame, Frame, ... ]
   │  ④ 可视化回放器（React 组件按帧渲染）
   ▼
变量盒子 / 数组网格 / 输出打字机 / 循环轮盘
```

**执行帧（Frame）数据结构**

```ts
interface Frame {
  step: number;                  // 第几步
  line: number;                  // 当前执行到源码第几行（用于高亮）
  col?: number;
  action: 'declare' | 'assign' | 'input' | 'output'
        | 'cond' | 'loop-init' | 'loop-test' | 'loop-step'
        | 'array-write' | 'array-read' | 'call' | 'return';
  vars: Record<string, VarSnapshot>;   // 这一步之后的全部变量快照
  stdout: string;                      // 到这一步为止的累计输出
  loopStack: LoopInfo[];               // 循环嵌套栈（用于轮盘渲染）
  note: string;                        // 中文人话解释，如「a 变成 8 了」
  highlight?: { varName?: string; arrayIndex?: number[] };  // 高亮对象
}

interface VarSnapshot {
  name: string;
  type: 'int' | 'long' | 'float' | 'double' | 'array' | 'array2d';
  value: number | string | number[] | number[][];
  changed: boolean;              // 本步是否变化（驱动闪烁动画）
  boxSize: 'small' | 'big';      // int 用小红盒，long 用大蓝盒（视觉区分）
}
```

**安全与健壮性**

- 步数上限 `MAX_STEPS = 20000`，超限中止并提示「这个循环好像跑不完哦」
- 解析失败给出**儿童化报错**：「第 3 行好像少了一个分号 `;`」
- 禁止任何 `eval` / `Function` 构造；纯 AST 求值，无代码注入风险
- 输入数据（cin）由题目的测试用例预置，**不做真实交互式输入**，避免孩子卡住

**可视化组件映射**

| 执行动作 | 可视化表现 |
|---|---|
| `declare` | 一个新的盒子飞入「变量区」，显示名字和初值 |
| `assign` | 盒子里的数字变化 + 盒子抖动 + 数字滚动动画 |
| `output` | 底部「话筒区」打字机逐字冒出 |
| `cond` | 条件表达式高亮 + 真/假分岔路动画 |
| `loop-test` / `loop-step` | 循环轮盘指针转动，显示「第 3 圈」 |
| `array-write` | 对应格子点亮 + 数字落格 |
| `array-read` | 对应格子放大 + 数据飞出 |

**引擎单测要求**：对参考资料的每道程序阅读题，均需有「源码 + 输入 → 期望 Trace 末尾 stdout」的用例，覆盖率 100%。

### 6.3 核心模块二：拖拽积木引擎（确认项 6）

**设计取舍**：不引入 Blockly（体积大、生成的积木块偏「图形化编程」，与考纲「写 C++ 语句」的目标偏离）。改为自研**「代码骨架 + 可拖槽位」**模式——保留真实 C++ 语法外观，只把易错片段变成积木。

**四种积木输入模式（难度递进）**

| 模式 | 说明 | 示例 |
|---|---|---|
| L1 填空式 | 代码骨架留 `___` 槽，拖入值/运算符 | `if (a ___ b) cout << a;` 槽里拖入 `>` |
| L2 整行排序 | 打乱的整行语句按顺序拖排 | 把 `int main(){` … `}` 排对 |
| L3 片体积木 | 拖入 `for (i=0; i<n; i++)` 这样的片段 | 拼出完整循环 |
| L4 积木建程序 | 用积木区拖出完整程序达成题目目标 | 拼一个求最大值程序 |

**交互细节（手机优先）**

- 积木**吸附**：拖到槽位附近 40px 内自动吸附并高亮
- **触觉反馈**：`navigator.vibrate(10)`（Android 支持，iOS 降级为缩放动画）
- **防误触**：长按 150ms 才进入拖拽，避免误划
- 积木区固定在屏幕底部，采用**横向可滚动托盘**，单手拇指可达
- 支持「点选 → 点击槽位」的备选方式（拖拽失败时的无障碍路径）
- **静态校验**：填入后立即做类型/语法合法性检查，给出即时反馈（不等到提交）

### 6.4 核心模块三：题库与内容引擎

- 题库以 **TypeScript 模块**形式分区域拆包（`import()` 动态加载），实现按需加载，避免首屏过大
- 每区域一个 chunk，进入区域时才加载，配合 PWA 预缓存策略
- 构建期用 Zod 对全部题库做 schema 校验 + 唯一 ID 校验 + 答案完整性校验，**校验不过直接构建失败**（防止手写题库出错）

### 6.5 核心模块四：进度与存档

- 存储介质：**Dexie (IndexedDB)** 为主，localStorage 存轻量配置
- 存储内容：关卡星级、答题历史、错题本、连击天数、昵称头像、设置项
- **一键导出存档**：生成 `.json` 文件，通过 Web Share API / 下载链接保存到手机，用于换设备迁移或防误清
- **一键导入**：文件选择器读取恢复
- 云同步：不做（确认项 4）

### 6.6 核心模块五：PWA 与离线

- `vite-plugin-pwa` 预缓存：HTML / JS / CSS / 图标 / 已加载题库 chunk
- 精确的 `manifest.webmanifest`：名称「信息学闯关」、竖屏 `portrait`、`display: standalone`、主题色
- 首次访问后自动提示「添加到主屏幕」引导层（iOS Safari 需手动教一次，配图示）
- 离线时：已缓存的关卡可正常闯关并本地存档；未缓存区域给出友好提示

### 7.3 题库 JSON / TS Schema（示意）

```ts
export const LevelSchema = z.object({
  id: z.string().regex(/^[A-F]\d{2}-\d{2}$/),   // 区域-章节-序号
  region: z.enum(['A','B','C','D','E','F']),
  chapter: z.string(),
  title: z.string(),
  type: z.enum([
    'math-choice','math-fill','math-step','math-manip',
    'code-read','code-fill','code-order','code-fix','code-build',
    'algo-demo','match'
  ]),
  // 生活化讲解（强制 4 段）
  life: z.object({
    scene:  z.string(),            // 1. 生活场景
    action: z.string(),            // 2. 动手做什么
    bridge: z.string(),            // 3. 抽象到符号
    backToCpp: z.string(),         // 4. 回到 C++ / 数学本身
  }),
  statement: z.string(),           // 题干
  payload: z.unknown(),            // 各题型专属数据（选项、代码、槽位、用例）
  answer: z.unknown(),             // 标准答案
  explanation: z.string(),         // 答后解释
  hints: z.array(z.string()).max(3), // 最多 3 级提示
  stars: z.object({ two: z.number(), three: z.number() }),
  source: z.object({               // 来源标注（确认项 2）
    kind: z.enum(['original','adapted','pastpaper']),
    from: z.string().optional(),   // 如「2024 选拔卷 第 9 题」
  }),
  difficulty: z.number().int().min(1).max(5),
});
```

## 9. 部署方案（群晖 NAS / Docker / x86）

### 9.1 容器化

**多阶段 Dockerfile（示意）**

```dockerfile
# ---------- 构建阶段 ----------
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run validate:content && npm run build

# ---------- 运行阶段 ----------
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget -qO- http://127.0.0.1/ >/dev/null || exit 1
```

**docker-compose.yml（示意）**

```yaml
services:
  infostar:
    build: .
    image: infostar:latest
    container_name: infostar
    restart: unless-stopped
    ports:
      - "8081:80"
    environment:
      - TZ=Asia/Shanghai
```

**nginx.conf 关键点**

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    # 前端路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # hash 文件名强缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # Service Worker 与清单不缓存，保证更新生效
    location = /sw.js { add_header Cache-Control "no-cache"; }
    location = /manifest.webmanifest { add_header Cache-Control "no-cache"; }
}
```

### 9.2 部署步骤（群晖 Container Manager）

1. 本机 `npm run build` 或直接用 Dockerfile 在 NAS 上构建
2. 群晖 **Container Manager → 项目 → 新增**，选择含 `docker-compose.yml` 的目录
3. 启动后访问 `http://<NAS局域网IP>:8081`
4. 手机浏览器打开 → 添加到主屏幕
5. 在路由器为 NAS 保留固定局域网 IP，避免地址变化

### 9.3 ⚠️ 关键决策点：局域网 HTTP 下 Service Worker 不可用

**问题**：浏览器安全策略规定，**Service Worker 仅在 HTTPS 或 `localhost` 下可用**。您的部署是「NAS 局域网 IP + HTTP（`http://192.168.x.x:8081`）」，这会导致：

- ❌ PWA 离线缓存（Service Worker）**无法注册**
- ❌ 断网后无法继续使用
- ⚠️ 「添加到主屏幕」部分可用（manifest 生效），但 `display: standalone` 的完整离线体验降级

**这不是可以绕过的限制，必须做一次取舍。给出三个方案：**

| 方案 | 做法 | 优点 | 代价 | 推荐度 |
|---|---|---|---|---|
| **A. 内网 HTTPS + Let's Encrypt** | 用一个自有域名做 **DNS-01 验证**签发证书（证书签发不需要公网可访问，只需 DNS 记录可控），DNS 解析到 NAS 内网 IP；群晖反向代理挂证书 | Service Worker 可用，PWA 完整，离线可用；**流量不出局域网** | 需要一个域名；手机上需自备 DNS（或用群晖 DNS Server 做内网解析） | ⭐⭐⭐⭐⭐ |
| **B. 群晖自签证书** | 群晖自带自签证书 + 反向代理 | 零成本，纯内网 | 每台手机首次访问需手动信任证书，孩子/老人操作门槛高 | ⭐⭐⭐ |
| **C. 放弃离线，只做在线** | 接受 HTTP，不注册 SW | 零成本，最简单 | 无离线；但**进度存档用 IndexedDB，仍可正常保存**，只是内容需联网加载 | ⭐⭐⭐（可接受的最小方案） |

> **本方案建议**：优先 **A**。若您不愿引入域名，则退到 **C**——注意此时**一切功能仍然正常**，唯一损失是「断网可用」这一项。产品设计上我会把 PWA 离线做成**渐进增强**：有 SW 就离线可用，没有就静默降级，不报错、不提示。
>
> **待您确认**：选 A / B / C？若选 A，请提供可用的域名（含 DNS 托管平台）。

- [ ] 是否有明确的**生活化场景**（四段式齐全：场景/动手/抽象/回到 C++）
- [ ] 题干是否只用到考纲内知识点（不越界到 while、函数、指针、结构体）
- [ ] 答案是否唯一（选择题）/ 是否接受等价写法（填空题）
- [ ] 难度是否落在 1–5 区间且与相邻关卡平滑递增
- [ ] 是否提供 ≤ 3 级提示，且提示不直接给答案
- [ ] 解释是否用小学语言（避免「算法复杂度」「时间复杂度」等术语）
- [ ] 有无角色名统一（统一使用「小明/小红」等，避免混乱）
- [ ] 图片/SVG 是否自绘且体积达标

### 10.3 难度分布目标

| 难度 | 占比 | 定位 |
|---|---|---|
| 1（入门） | 20% | 每章前 1–2 关，建立信心 |
| 2（基础） | 30% | 概念巩固 |
| 3（标准） | 30% | 对标真题常规题 |
| 4（进阶） | 15% | 对标真题压轴 |
| 5（挑战） | 5% | 决赛/复试级 |

## 11. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|

| R10 | 色彩/字号不适合儿童阅读 | 中 | 正文 ≥ 16px；对比度符合 WCAG AA；无纯红纯绿强刺激（考虑色盲） |

## 15. 结论

本方案以**考纲为唯一内容边界**，以**纯前端可视化执行**为技术抓手，以**「生活化类比四步法」**为教学内核，以**闯关地图 + 星级**为动机系统，以**群晖 Docker 单容器**为交付形态，形成一条「内容有据、技术可控、体验适配手机、部署维护极简」的完整路径。

**关键建议**：第一阶段（MVP）不要贪多，**只做 2 个主题 12 关，但必须把整条闭环跑通**——地图、关卡、答题、可视化运行、星级、存档、PWA、部署，一个都不能少。闭环打通后，剩下的工作就变成了「往一个已经跑通的容器里不断加内容」，风险与成本都会大幅下降。
